# GuessWho Arena

Многопользовательская игра «Угадай кто?» на React, TypeScript и PostgreSQL. Русский и английский интерфейс, 4 колоды по 32 персонажа, локальные WebP-портреты, чат, WebRTC-голос, тренировка с ботом, монеты и косметические предметы.

## Запуск на ноутбуке

Требуется Node.js 22.12+ или 24 LTS. На Windows запустите `start.bat`: скрипт соберёт игру, поднимет сервер в фоне и сохранит базу в `server/.data`.

- На ноутбуке: http://localhost:3000
- В домашней сети: `http://IP-НОУТБУКА:3000`
- Временный HTTPS-адрес: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/start-tunnel.ps1`
- Остановка: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/stop-local.ps1`

Сайт работает, пока ноутбук включён и процессы запущены. HTTPS-ссылка меняется после нового запуска туннеля. Для микрофона на телефоне используйте HTTPS. Не удаляйте `server/.data`: там находятся профили, комнаты, переписка, монеты и покупки.

Профиль определяется сессией браузера; другой браузер или очистка данных сайта создают новый профиль. Для сохранения прогресса между сменами адреса используйте код переноса на странице профиля. Локальная база не отправляется в Git.

База — PostgreSQL через PGlite с хранением на диске. Docker и облачный аккаунт для локального режима не требуются. При переносе в Supabase используется та же SQL-схема и серверные функции.

## Визуальный просмотр базы

При запуске игрового сервера открывается отдельная локальная панель: http://127.0.0.1:3002. Она показывает пользователей с монетами и Elo, комнаты, друзей, колоды и награды огонька. Есть поиск, сортировка, страницы по 50 строк и подробности по нажатию на запись. Данные обновляются кнопкой «Обновить».

Панель работает только на loopback-интерфейсе ноутбука, проверяет Host и Origin и не публикуется игровым туннелем. Она не позволяет изменять данные и не показывает сессии, коды восстановления или секреты матча. Используется уже открытый экземпляр базы игрового сервера. `DB_VIEWER_PORT` меняет порт; значение `0` отключает панель.

## Разработка и проверки

```sh
npm ci
npm run dev
npm test
npm run build
npm start
node tools/local-smoke.mjs http://127.0.0.1:3000
node tools/presence-smoke.mjs http://127.0.0.1:3000
```

`npm run dev` запускает Vite на 5173 и API на 8787. Не запускайте два сервера с одной базой одновременно: сначала остановите production-сервер либо задайте отдельный `DATA_DIR`. `npm start` обслуживает собранный `dist`, API и WebSocket на 3000. Переменные `PORT` и `DATA_DIR` переопределяют порт и путь базы.

Тесты проверяют SQL-авторизацию, приватность персонажей, очередность ходов, покупки, повторное начисление наград, локальные сессии, одновременные запросы, сохранение базы при перезапуске и наличие WebP для всех 128 персонажей. Smoke-тест проходит HTTP/WebSocket-сценарий двух игроков. Проверка присутствия занимает около 67 секунд и проверяет реальное закрытие соединений и минутный таймер.

## Правила

Создайте комнату, передайте другу код, выберите по секретному персонажу. Задавайте вопросы с ответом «да» или «нет» в чате или голосом, исключайте карточки и передавайте ход. Неверная догадка закрывает карточку и передаёт ход сопернику. После верной догадки второй игрок получает ровно одну ответную попытку: верный ответ завершает матч вничью, неверный закрепляет победу первого игрока. Передавать последний ход нельзя. При смене хода звучит сигнал и появляется уведомление; прокрутка страницы не меняется.

Онлайн-победа приносит 50 монет, если матч длился не меньше 30 секунд и игроки передали ход минимум дважды. Максимум 20 наград за 24 часа. Тренировки могут принести ежедневную награду огонька. Выход из матча не приносит монет. Магазин содержит только косметику, реальные платежи не используются. Баланс, победы и покупки меняют серверные функции.

Рейтинг начинается с 1000 Elo, коэффициент K = 32. Победа над равным игроком даёт 16 очков. Рейтинг меняется после 30 секунд и двух ходов; выход из такого матча считается рейтинговым поражением. Ничья считается как 0,5 очка: равные рейтинги не меняются, при разных рейтингах более слабый игрок получает очки. За ничью победная награда и победные достижения не выдаются; ежедневный огонёк засчитывается. Повторное завершение матча не начисляет награды и рейтинг снова.

Доступны 12 титулов с прогрессом, включая Сенпая за 5 суммарных побед в двух аниме-категориях, Чародея за 5 побед в Гарри Поттере и Мстителя за 5 побед в Marvel. Титулы выбираются в профиле. Победы по категориям засчитываются в полноценных матчах без выхода соперника.

Фотографии профиля загружаются в JPG, PNG, WebP или GIF до 8 МБ, обрезаются до квадрата и сохраняются в WebP 256 × 256. Данные хранятся в PostgreSQL, доступны после восстановления профиля и отображаются другим игрокам.

Друзья добавляются по 10-значному коду. Заявка требует принятия получателем. Другу можно отправить приглашение в приватную комнату; оно действует 15 минут. В чате доступны 12 базовых реакций и 19 реакций из магазина. На телефоне сообщения показываются уведомлениями без прокрутки страницы; чат открывается отдельной панелью.

Для административного начисления монет остановите сервер и выполните `node tools/grant-coins.mjs PLAYER_NAME AMOUNT`. Команда откажется работать с запущенным сервером и при нескольких совпадающих именах. В публичном API административного начисления нет.

При отключении одного игрока комната сохраняется 60 секунд для возвращения. Когда отключились оба участника, комната сразу закрывается и исчезает из активных списков. Если один не вернулся за минуту, оставшийся игрок получает победу за выход соперника без монет; отключение обоих отменяет матч без победы и поражения. История завершённых матчей сохраняется.

## Пользовательские колоды и профили

Раздел «Колоды» позволяет создать пак с нуля или настроить копию любой доступной категории. Пак содержит 6–64 персонажа, каждому нужны имя и фотография. Поддерживается загрузка нескольких фото, преобразование в WebP 300 × 366, английские названия и признаки для вопросов бота. На профиль доступно до 20 паков. Личные паки видны автору; другие игроки могут играть ими по приглашению в комнату. Опубликованные паки доступны всем авторизованным игрокам.

Матч получает неизменяемую копию состава при создании комнаты. Последующее редактирование исходного пака не меняет активные матчи. У каждого игрока один голос за опубликованный чужой пак: лайк или дизлайк можно сменить или снять повторным нажатием.

Юзернеймы уникальны без учёта регистра и пробелов по краям. При регистрации с занятым именем добавляется суффикс; при ручной смене занятое имя отклоняется. В существующей базе дубли получают суффиксы с сохранением профиля, монет и истории. Золотой и фиолетовый значки верификации назначаются только на сервере; надписей с должностями нет.

В профиле доступны количество и процент побед, поражений и ничьих, фильтр по сопернику и последние 30 встреч. Отменённые комнаты исключены. Статистику конкретного соперника можно открыть кнопкой VS в матче.

## Supabase и Vercel

1. Создайте проект Supabase.
2. Выполните по порядку SQL-файлы из `supabase/migrations` в SQL Editor или через Supabase CLI.
3. В Authentication включите Anonymous Sign-Ins. Для массового запуска настройте CAPTCHA и лимиты регистрации.
4. Скопируйте `.env.example` в `.env`; задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`. Используйте публичный ключ, не серверный секрет.
5. В Vercel импортируйте репозиторий, выберите Vite и добавьте те же две переменные. Настройки сборки и маршрутов уже находятся в `vercel.json`.
6. Пересоберите и опубликуйте приложение. При наличии этих переменных клиент использует Supabase вместо API ноутбука.

Локальные данные не переносятся в облако автоматически. Пока проект Supabase не создан, приложение работает с локальной базой.

## Дружеские матчи и огонёк

При создании комнаты можно выбрать рейтинговый или дружеский режим. В дружеском матче Elo и число рейтинговых игр не меняются при любом исходе, включая выход и отключение. Статистика встреч и обычные награды за полноценную победу сохраняются. Приглашения друзьям по умолчанию дружеские.

Кнопка «Поле соперника» показывает его открытые и закрытые карточки. Состояние хранится на сервере и обновляется в реальном времени. Секрет соперника в этот ответ не включается. Нажатие на его аватар открывает заявку в друзья или принятие входящей заявки.

Огонёк зажигается после завершённой игры: победы, поражения или ничьей в онлайне либо тренировки с ботом при подключении к серверу. Простое посещение и выход из матча не засчитываются. День меняется в 00:00 UTC+5; пропуск дня сбрасывает текущую серию, сохраняя рекорд и подарки. На обычный день начисляется 25 монет; на 3-й — 75, на 7-й — 150 и реакция 🔥, на 14-й — 300 и неоновая рамка, на 30-й — 750 и золотая рамка. После 30 дней каждый седьмой день приносит 225 монет. Награда начисляется автоматически один раз в день.

## Голос

Панель микрофона находится над игровым полем. Голос разрешён только двум участникам комнаты с принятой дружбой; сервер проверяет это при подключении и передаче сигналов. Удаление из друзей отключает голос. Заявку можно отправить и принять через аватар в матче.

WebRTC передаёт аудио между игроками; события установления соединения проходят через авторизованный WebSocket или приватный Supabase Realtime-канал. Микрофон включается только нажатием кнопки, остаётся активным после завершения матча и останавливается при выходе или ручном отключении, поддерживается заглушение.

STUN включён по умолчанию. Для пользователей за сложным NAT или в сетях, блокирующих прямые соединения, настройте `TURN_URL`, `TURN_USERNAME`, `TURN_CREDENTIAL` на сервере либо в Vercel. ICE-настройки выдаются только авторизованным игрокам. Для мобильного голосового чата нужен HTTPS и разрешение на микрофон.

## Изображения

Игровые изображения находятся в `public/images`, размер 360 × 440, формат WebP. Каталог: `src/data/catalog.json`. Источник каждого портрета: `data/asset-sources.json`. Для пересоздания установите Pillow и выполните `npm run assets`.

Источники: Attack on Titan API, Dattebayo API / Narutopedia, HP API, PotterAPI, Harry Potter Fan Zone, Superhero API. Персонажи и иллюстрации принадлежат правообладателям соответствующих произведений; это неофициальный фан-проект. Источники изображений не означают предоставления коммерческой лицензии.

## Структура

- `src/pages` — отдельные экраны
- `src/components` — оболочка, карточки, модальные окна
- `src/lib` — транспорт, голос, звук, логика, настройки
- `server` — локальный HTTP/WebSocket-сервер и PostgreSQL
- `supabase/migrations` — схема, политики доступа и серверные функции
- `api/ice.js` — Vercel endpoint для ICE/TURN
- `tests` — автоматические проверки
- `tools` — запуск, туннель, изображения, smoke-тест

В исходный код не добавлены комментарии.
